# Mesh cleanup methods: smooth shading on a rough high-poly car body without changing its shape (Blender 4.x/5.x, Assetto Corsa)

Scope: the Nova GTE body is one ~1.2M-triangle bought/hobby mesh with custom split normals. Symptoms: zig-zag (triangulated) crease lines, rippled reflection streaks on bumpers and sills, ragged panel-gap edges, small crumpled panels. A bilateral-normal denoise capped at 1 mm barely helped. Constraint: keep shape within about 1-2 mm except where a panel is genuinely crumpled.

Source access notes: the Blender manual pages were read in full (current "latest" manual, which is the 5.x line). Polycount (polycount.com) returned HTTP 403 to every fetch and is not in the Wayback Machine, so every Polycount finding below comes from search-result excerpts only and is marked that way. projects.blender.org bug pages were also blocked (403 / Cloudflare), so bug details come from search-result titles and excerpts only. I found no Assetto Corsa-specific guide on body shading; AC findings are thin and noted as such.

## 1. Normal transfer: Data Transfer modifier (custom normals / face-corner data) from a smoothed, subdivided or remeshed proxy onto the original mesh

### Takeaway
Copying custom normals from a clean proxy onto the original mesh is the standard way game artists make a dense or awkward mesh shade like a clean surface without moving any vertex. Blender's Data Transfer modifier does it natively. For a mesh that is a smoothed duplicate of itself (same vertex count and order), the manual's **Topology** mapping is an exact one-to-one match; for a remeshed or retopologised proxy, **Nearest Face Interpolated** or **Projected Face Interpolated** apply. It hides surface noise in the shading only. It does not fix the silhouette or the geometric path of a jagged crease, and it softens creases unless you protect them.

### Cited Findings
- The Data Transfer modifier "copies certain types of data from an external mesh to the modified one. This could be UV maps, color attributes, custom normals, and so on." — [Blender Manual: Data Transfer Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/modify/data_transfer.html)
- Usage per manual: pick the Source; "If the source mesh and modified mesh aren't overlapping in world space, uncheck Object Transform"; pick the data type; click **Generate Data Layers** for missing layers, because "the modifier doesn't do this automatically ... the transfer may not work otherwise." — [Blender Manual: Data Transfer](https://docs.blender.org/manual/en/latest/modeling/modifiers/modify/data_transfer.html)
- Mix options: **Mix Mode** (Replace, Above/Below Threshold, Mix, Add, Subtract, Multiply), **Mix Factor** ("Interpolation factor between the original destination value and the newly calculated value"), and a **Vertex Group** that "allows per-element control of the Mix Factor" (invertible). — [Blender Manual: Data Transfer](https://docs.blender.org/manual/en/latest/modeling/modifiers/modify/data_transfer.html)
- **Topology** mapping "Simply matches the elements based on their index. This requires both meshes to have the same number of elements and those elements to be ordered in the same way. Best suited for a destination mesh that's a deformed copy of the source." — [Blender Manual: Data Transfer](https://docs.blender.org/manual/en/latest/modeling/modifiers/modify/data_transfer.html)
- Face-corner one-to-one mappings: "Nearest Corner and Best Matching Normal" (nearest source corner with the most similar split normal), "Nearest Corner and Best Matching Face Normal", "Nearest Corner of Nearest Face". — [Blender Manual: Data Transfer](https://docs.blender.org/manual/en/latest/modeling/modifiers/modify/data_transfer.html)
- Face-corner interpolated mappings: "Nearest Face Interpolated: Find the nearest point on the nearest source face, then use that point to interpolate between the values of the face's corners." "Projected Face Interpolated: Project the destination corner along its normal onto a source face, then use the projected point to interpolate between the values of the face's corners." — [Blender Manual: Data Transfer](https://docs.blender.org/manual/en/latest/modeling/modifiers/modify/data_transfer.html)
- **Max Distance**: "source and destination elements that are further away from each other than the specified distance will not be considered as matches." **Ray Radius**: "use a low radius for dense source meshes and a high one for simple ones." **Islands Precision** applies to UV islands only. — [Blender Manual: Data Transfer](https://docs.blender.org/manual/en/latest/modeling/modifiers/modify/data_transfer.html)
- Blender 4.1 removed Auto Smooth: "The 'Auto Smooth' option has been replaced by a modifier node group asset." "The base state of meshes is now the same as having 'Auto Smooth' on with an angle of 180 degrees in older versions." "Custom normals are used if available." "Face corner 'split' normals are calculated when there is a mix of sharp and smooth elements." — [Blender 4.1 Release Notes: Modeling](https://developer.blender.org/docs/release_notes/4.1/modeling/)
- Python API 4.1: `use_auto_smooth` removed ("Face corner normals are now used automatically if there are mixed smooth vs. not smooth tags"); `auto_smooth_angle` "Replaced by a modifier (or operator) controlling the 'sharp_edge' attribute"; `calc_normals_split` and related removed in favour of `Mesh.corner_normals`; `MeshLoop.normal` is read-only, and custom normals are set with `normals_split_custom_set` or `normals_split_custom_set_from_vertices`. — [Blender 4.1 Release Notes: Python API](https://developer.blender.org/docs/release_notes/4.1/python_api/)
- Pre-4.1 forum advice that "the transfer only store[s] custom normal data for Auto Smooth mode" (so Auto Smooth had to be on) is obsolete for 4.1+. — [Polycount thread, search excerpt only (page 403)](https://polycount.com/discussion/comment/2676952/); superseded per [Blender 4.1 Release Notes](https://developer.blender.org/docs/release_notes/4.1/modeling/)
- Polycount advice for racing-game car meshes: build a subdivision high-poly, reduce its cage to the target count, and "transfer vertex normals" to the low-poly, "like baking a normal map to the vertices"; vertex attributes avoid texture compression and interpolation artifacts; the poster added they did not know "if it will work for an entire car". Another user said it "works reasonably well, but its not perfect", works better from a source at subd level 1 or 2, and a low base still shows some odd shading "unless you unleash sharper edges or other tricks". — [Polycount 2426371, search excerpt only](https://polycount.com/discussion/comment/2426371); [Polycount 2787669, search excerpt only](https://polycount.com/discussion/comment/2787669)
- Polycount: manual averaging/tweaking of normals is "(usually) not suitable" for this, where transfer works; one commenter said a commercial normal-transfer add-on "just seems to be a handy shortcut for something the data transfer modifier/operator can do by default"; transfer from a copy of the body without tertiary detail. 3ds Max equivalent named: "Noors Normal Thief". — [Polycount 2425875, search excerpt only](https://polycount.com/discussion/comment/2425875); [Polycount 2787652, search excerpt only](https://polycount.com/discussion/comment/2787652)
- Blender Artists tutorial series (Blender 3.1): "We'll model the shapes we want separately, then steal their Normals and put them onto our main mesh"; it covers basic Data Transfer setups and using "multiple Data Transfers and multiple Source and Destination meshes" to work around limits. — [Blender Artists: Customizing Normals tutorial series](https://blenderartists.org/t/customizing-normals-tutorial-series/1369038)
- Known bug titles (details not readable, 403): "Normals not properly updating when using a Deform modifier after a Data Transfer (Custom Normals) modifier #94838" (excerpt suggests an Edge Split between them as a workaround); "Data Transfer modifier not working with Vertex Groups in 4.1 Alpha #117520" (excerpt: problem with vertex-group weights between 0 and 1; fix status unknown); "Custom normals corrupted by triangulation after data transfer modifier is applied #44878" (2015). — [Blender #94838](https://projects.blender.org/blender/blender/issues/94838); [Blender #117520](https://projects.blender.org/blender/blender/issues/117520); [Blender T44878](https://developer.blender.org/T44878)
- Edit-mode custom-normal tools exist for local touch-up: **Smooth Vectors** ("Smooths out the custom normals of each selected vertex by averaging with the normals at neighboring vertices", Factor option), **Average**, **Set from Faces** (with Keep Sharp Edges), **Reset Vectors**, **Point to Target**. — [Blender Manual: Normals (Edit Mode)](https://docs.blender.org/manual/en/latest/modeling/meshes/editing/mesh/normals.html)
- The Normal Edit modifier can also mix generated normals with a Max Angle limit and Lock Polygon Normals; the manual itself points to Data Transfer for "More complex normal manipulations ... copying normals from one mesh to another". — [Blender Manual: Normal Edit Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/normals/normal_edit.html)
- Shading check used by game car artists: apply a reflective matcap often while modelling, because it "helped me spot any shading errors or inconsistencies with the topology". — [The Rookies: Production Process for 3D Vehicle Assets for Games (Rinalds Bitte, 2024)](https://www.therookies.co/blog/breakdowns/production-process-vehicle-assets-games)

### Inferences
- **Why the 1 mm bilateral denoise barely helped:** reflection streaks on bumpers and sills come from normal variation at wavelengths of several mm to cm. A displacement cap of 1 mm cannot flatten a wave of that length. A normal-only method has no displacement at all, so the source proxy can be smoothed as hard as needed (moving the proxy by several mm) while the exported shape stays identical. This fits the "no reshaping" constraint better than any vertex smoother.
- **Recommended Blender 5.x recipe ("smoothed twin + Topology mapping")**, built from the manual options above:
  1. Duplicate the body (Shift+D, right-click to cancel the move) and name it e.g. `Body_NormalSource`. Do not change its topology.
  2. On the duplicate, smooth the geometry hard: a Corrective Smooth (Only Smooth on, Length Weight, Repeat high, Pin Boundaries on) or Smooth Laplacian (Preserve Volume, Normalized) modifier, restricted by a vertex group that excludes true creases and panel-gap lips (weight 0 there). See Q5. Apply it.
  3. On the original, add Data Transfer: Source = `Body_NormalSource`; Face Corner Data on, Custom Normals; Mapping = **Topology** (exact, because the twin is a "deformed copy"). Mix Mode Replace, Mix Factor 1 (or 0.5-0.8 to keep some of the original), and a Vertex Group to fade the effect out near creases and gaps.
  4. Mark the true creases and panel-gap boundary edges sharp (Edge > Mark Sharp, i.e. the `sharp_edge` attribute) so shading still breaks there. Do not add Smooth by Angle on top unless you want angle-based sharpness as well.
  5. Check with a reflective matcap (Rookies) from several angles, then apply the modifier before FBX export. Keep Data Transfer last in the stack: nothing that deforms or retopologises after it (bugs #94838 and T44878).
- **Alternative proxies** (when a smoothed twin still carries the zig-zag): a Remesh-modifier proxy (Sharp mode, low Sharpness, so noise is filtered and edges kept), a Voxel remesh plus sculpt Surface Smooth, or a clean quad cage with Subdivision Surface at level 1-2 (Polycount reports level 1-2 sources work better). These need **Nearest Face Interpolated** or **Projected Face Interpolated**, plus Max Distance of a few mm so corners on inner sheets (door jambs, shut faces, the panel underside) do not pick up normals from the outer skin. On thin, double-sided areas, Projected Face Interpolated or "Nearest Corner and Best Matching Normal" is less likely to grab the wrong sheet than plain nearest-face.
- **Limits:** (a) normals only, so the silhouette and the jagged geometric path of a crease are unchanged (a zig-zag crease will still show where the highlight is cut by the sharp edge); (b) a strongly smoothed source rounds creases, so without vertex-group or sharp-edge protection the crease highlights go soft; (c) any later topology change (triangulate, decimate, weld) can scramble the stored custom normals, so finish the geometry first. The body is already triangles, so KN5 triangulation should not change topology.
- With 1.2M triangles, Topology mapping is the cheapest to evaluate (index match, no ray casts). Ray-cast mappings on a 1.2M source and destination will be slow; apply once and work on panels separately if needed.

## 2. Weighted Normal modifier / face-weighted normals on hard-surface car panels

### Takeaway
Face-weighted normals are a mid/low-poly hard-surface trick: big flat faces dominate the vertex normal so the shading bends only across small bevel faces. On a dense, curved 1.2M-triangle body it adds little, and it is not a denoiser. The one place it may help is a triangulated crease where long thin sliver triangles skew the normals (Face Area weighting reduces their influence). That is untested.

### Cited Findings
- The modifier "changes the custom normals of a mesh ... useful to make some faces appear very flat during shading". Weighting Modes: **Face Area** ("A larger area means that the normal from that face will get a higher weight"), **Corner Angle** ("the method Blender uses by default"), **Face Area and Angle**. **Weight** 50 = uniform, above 50 = more "contrast". **Threshold** rounds near-equal weights. **Keep Sharp** preserves sharp edges "though smoothing will still happen if there are multiple faces between any two Sharp edges". **Face Influence** uses Weak/Medium/Strong face strengths from Set Strength or the Bevel modifier. A **Vertex Group** limits it. — [Blender Manual: Weighted Normal Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/normals/weighted_normal.html)
- Polycount wiki: FWN improves shading "by adding bevels and altering the vertex normals to be perpendicular on the larger flat polygons. This forces the shading to be blended across the smaller bevel faces, rather than across the entire model." Caveat: "the added bevels will often create long thin triangles, which can significantly reduce rendering performance." Tools listed: 3ds Max Weighted Normals modifier, Blender Weighted Normal modifier. — [Polycount Wiki: Face weighted normals](http://wiki.polycount.com/wiki/Face_weighted_normals)
- A Blender regression report exists titled "Weighted Normal + Auto Smooth gives broken shading #121620" (details not readable). — [Blender #121620](https://projects.blender.org/blender/blender/issues/121620)
- Game car bodies are usually built "mid poly" with smoothed normals and "surface continuity" as the priority, or baked. — [80.lv: Vehicle Production for Games (Karol Miklas)](https://80.lv/articles/vehicle-production-for-games/)

### Inferences
- **When it helps on a car:** flat-ish panels with a deliberate chamfer or fillet at the edge (bonnet lip, sill step, bumper top edge, window frames), especially on a lower-poly LOD. Mark the chamfer faces Weak and the big faces Strong (Set Strength / Bevel modifier) and use Face Influence.
- **When it does not help:** continuously curved panels (doors, wings, roof). There, all faces around a vertex have similar area and angle, so FWN results are nearly identical to default smoothing. It does not remove ripples, because the ripples are real geometry undulation.
- **Possible use on zig-zag creases (to test):** with Face Area mode and Keep Sharp, sliver triangles from bad triangulation along a crease get little weight. This may calm the "sawtooth" shading beside a crease. Restrict with a vertex group on the crease band only.
- **Stack order:** Weighted Normal and Data Transfer both write custom normals; the last one in the stack wins (blended by its mix factor). Use one or the other per region, or put Weighted Normal on the crease band and Data Transfer (with an inverted group) elsewhere.

### Gaps
- No source describes FWN results on a dense car body; the guidance above is inferred from the manual and the Polycount wiki.
- Details of bug #121620 and whether it affects 5.x could not be read.

## 3. Retopology approaches for car bodies, and best result vs effort for cleaning an existing detailed body

### Takeaway
Professional game car bodies are normally built as clean quad subdivision surfaces with support loops, not cleaned from scans. Full retopology gives the best surface but is a near-rebuild. Auto-remeshers (QuadriFlow, Quad Remesher, Instant Meshes) handle broad curvature but break small bevels and panel-line detail on hard surfaces. For cleaning an existing detailed body, the best ratio is: (1) normal transfer from a smoothed twin (no shape change), (2) local vertex smoothing with vertex groups, (3) local quad rebuild only for genuinely crumpled panels, shrinkwrapped and subdivided, and auto-remesh used as a normals proxy rather than as final geometry.

### Cited Findings
- Game car workflow: subdivision modelling in Blender with a Mirror modifier; "it was vital to keep the mesh in quads to ensure no pinching or artefacts appear"; supporting loops where edges need to be tighter. — [The Rookies (Rinalds Bitte, 2024)](https://www.therookies.co/blog/breakdowns/production-process-vehicle-assets-games)
- 80.lv (Karol Miklas, ex-Dying Light / Cyberpunk 2077 / PUBG): start from "an edge outline that works as a 3D blueprint", "plan topology in advance, before moving to surfaces creation", use "mirror or turbosmooth (subdivision surface)". — [80.lv: Vehicle Production for Games](https://80.lv/articles/vehicle-production-for-games/)
- BeamNG modder (Gabester): mid-poly body shell smoothed with "control edgeloops", kept in one smoothing group except at panel cutlines. — [BeamNG: Gabester's Blog, A look at vehicle workflow Part 1](https://beamng.com/posts/37582/)
- Blender Remesh (Data panel): **Voxel** gives uniform grid topology with no self-intersections, good for cleanup, but "should not be used for ... Generating a mesh for applying the Subdivision Surface Modifier"; settings Voxel Size, Adaptivity, Fix Poles, Preserve Volume. **Quad** uses QuadriFlow, is better for a subdivision base, but "doesn't clean up intersecting geometry"; options Use Mesh Symmetry, **Preserve Sharp**, Preserve Mesh Boundary, Smooth Normals, Mode (Ratio / Edge Length / Faces), Seed. Manual retopology: Retopology overlay, Poly Build tool, snapping to the original. — [Blender Manual: Remeshing / Retopology](https://docs.blender.org/manual/en/latest/modeling/meshes/retopology.html)
- Remesh **modifier** modes: Blocks, Smooth, **Sharp** ("preserves sharp edges and corners"; **Sharpness**: "Higher values produce edges more similar to the input, while lower values filter out noise"), Voxel. "The input mesh should have some thickness ... If the input is completely flat, add a Solidify Modifier above the Remesh one." — [Blender Manual: Remesh Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/generate/remesh.html)
- Shrinkwrap wrap methods: Nearest Surface Point; Project (axis, Negative/Positive, Face Cull, Limit, **Subdivision Levels** = temporary Catmull-Clark before the wrap); Nearest Vertex; **Target Normal Project**: "similar to Nearest Surface Point, but produces a much smoother projection in return for being significantly slower." Plus Offset and a Vertex Group for per-vertex influence. — [Blender Manual: Shrinkwrap Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/deform/shrinkwrap.html)
- Sculpt Mesh Filter **Erase Displacement** "can be used ... to fix reprojection artifacts after applying a Shrinkwrap Modifier" (Multires workflow). — [Blender Manual: Mesh Filter](https://docs.blender.org/manual/en/latest/sculpt_paint/sculpting/tools/mesh_filter.html)
- Copying normal data or shrinkwrapping "seems to work better on subd (maybe level 1 or 2)". — [Polycount 2787669, search excerpt only](https://polycount.com/discussion/comment/2787669)
- Quad Remesher on hard surface (Blender Artists, May 2023): small rounded bevels, "the curvature always ends up breaking"; on a car wheel arch "it gets it practically spot on"; normals splitting was "inconsistent"; best result came from adding small edge loops around the bevel and splitting normals perpendicular to the curve, but "Lots of cleanup is needed afterwards". Another user: QR "won't keep small bevel" and adds "edge loop everywhere". — [Blender Artists: Quad Remesher thread p.30](https://blenderartists.org/t/quad-remesher-auto-retopologizer/1170913?page=30)
- Third-party (render farm, not the vendor) guide: Quad Remesher places topology boundaries at creases above a configurable angle, default 30 degrees; mark hard edges on the source; it transfers geometry only, not UVs or vertex colours. — [SuperRenders Farm: Quad Remesher guide](https://superrendersfarm.com/article/quad-remesher-blender-retopology)
- Instant Meshes (Jakob, Tarini, Panozzo, Sorkine-Hornung, SIGGRAPH Asia 2015): solve an orientation field then a position field, then export; the fields "can also be manipulated using brush tools"; Modo has used the algorithm for automatic retopology since 10.2. — [Instant Meshes README (GitHub)](https://github.com/wjakob/instant-meshes)
- Scan-to-quad pipelines: wrap a clean base mesh onto the scan (R3DS Wrap), subdivide, project scan detail back with shrinkwrap; automatic options include QuadriFlow-based tools. Strip micro-detail and noise before retopology so the cage follows the main forms. — [ZHdK iaspace wiki: Retopology](https://iaspace.zhdk.ch/wiki/retopology/); [Sloyd: manual retopology guide](https://www.sloyd.ai/blog/manual-retopology-for-sculpted-models-step-by-step-guide)
- Keep the car as one uncut surface while modelling, cut panel gaps once surfaces settle, and keep the uncut mesh as a shrinkwrap reference so reflections stay continuous across panels. — [Polycount 2739861, search excerpt only](https://polycount.com/discussion/comment/2739861); [Polycount 1469163, search excerpt only](https://polycount.com/discussion/comment/1469163)

### Inferences
- **Best result vs effort for this body (ranked):**
  1. *Normal transfer from a smoothed twin* (Q1): minutes of work, zero shape change, fixes most streaks and ripples in shading. First thing to try.
  2. *Local vertex smoothing* with vertex groups on the worst bumper/sill bands (Q5): small real displacement, fixes geometry that normals cannot hide (silhouette waves). Measure displacement against an untouched copy.
  3. *Local quad patch rebuild* for genuinely crumpled panels and the worst crease runs: model a small quad grid over the area (Poly Build plus face snapping, Retopology overlay), add Subdivision Surface level 1-2 then Shrinkwrap (Target Normal Project, small Offset) to the original, smooth the patch afterwards, and either replace those triangles or use the patch only as a normals source.
  4. *Full body retopology* (manual quad cage over the whole car, subdivided): best surface and what pro artists build, but effectively a remodel (days of work) and it risks drifting from the bought shape. Only worth it if the body is also wanted as a clean subdivision base for future work.
  5. *Auto quad remesh as final geometry* (QuadriFlow / Quad Remesher / Instant Meshes): poor value for a car body. Panel lines, small fillets and gaps break and need heavy cleanup. Useful as a proxy for normals (with Preserve Sharp), not as the exported body.
- **Shrinkwrap pitfall:** shrinkwrapping a clean cage onto a noisy target copies the target's noise into the cage when the cage is dense. Keep the cage coarse (subd 1-2 as Polycount says), shrinkwrap before the final subdivision level, and/or shrinkwrap onto a pre-smoothed twin rather than the raw mesh.
- **Straightening crease loops:** in a triangulated mesh there is often no single edge loop along a crease. Practical options (inferred, untested here): cut a clean edge path along the crease with Knife Project from a curve, slide or straighten the nearby vertices onto it, or rebuild just a strip along the crease as a quad patch. Also see "Relax Face Sets" in Q5.

### Gaps
- No primary source compares these approaches specifically on a car body with timings; the ranking is my inference from the tool docs and practitioner reports.
- The official Quad Remesher documentation page (exoside.com) returned 404, so QR settings (Use Normals Splitting, Adaptive Size, etc.) are not verified here.
- No AC-community source on retopologising converted or bought car bodies was found.

## 4. Panel gaps on game cars: modelled grooves vs separate panels with thickness and shut faces; how gaps are shaded

### Takeaway
Two practices dominate. Sim and hero cars detach each panel, offset it a few mm, and give it a simple turned-in edge or underside plus modelled jambs and shut faces. Lower-poly cars keep a single edge (or a shallow groove) and sell the gap with texture, AO or a normal map. In both cases the body is shaded as one smoothing group across a panel and split (sharp) only at the cut lines, so reflections stay continuous across the gap.

### Cited Findings
- Gabester (BeamNG): whole shell in "one smoothing group, except at panel cutlines"; each panel detached and spaced "a few millimeters" apart; panel undersides simplified (flat, same grid as the outside, sharp character lines removed, some volume for panel depth); door jambs modelled from photos, with "the door is the inverse of the jamb"; long thin rubber seals UV-straightened to avoid aliasing; removable parts spaced apart so AO shadows do not appear when they fall off. — [BeamNG: Gabester's vehicle workflow](https://beamng.com/posts/37582/)
- Gabester: almost never bakes normal maps for whole cars; instead puts UV seams on hard edges, bakes a white mask at double resolution, makes as-is, expanded-1px and contracted-1px versions, runs each through a height-to-normal filter, and overlays them "to create beveled gaps"; AO baked from a skylight and multiplied into diffuse and specular. — [BeamNG: Gabester's vehicle workflow](https://beamng.com/posts/37582/)
- Polycount: place an edge loop where the gap belongs in the base mesh, smooth, and only then cut the gap so reflections stay continuous; for low poly "you don't need to open panel lines" and a single edge following the line with depth from texture is enough. — [Polycount 1469163, search excerpt only](https://polycount.com/discussion/comment/1469163); [Polycount 1209528, search excerpt only](https://polycount.com/discussion/comment/1209528)
- Workflow order reported on Polycount: blockout, then base mesh with panel folds and cuts, then high-poly detail, with support loops part of base-mesh refinement. — [Polycount 2787507, search excerpt only](https://polycount.com/discussion/comment/2787507)
- CAD analogue: Rhino's Shutlining "only modifies the display mesh. It does not change the geometry" (a display-only gap, like a texture or normal-map gap). — [Rhino Artisan: Shutlining](https://rhinoartisan.com/docs/6/rendering/commands/advanced/shutlining/)
- Real-car gap sizes: older cars could have panel gaps "as wide as a quarter-inch" (~6 mm), versus about 0.14 in (~3.5 mm) for today's highest standards. — [Capital One: Why Car Panel Gaps Matter](https://www.capitalone.com/cars/learn/finding-the-right-car/why-car-panel-gaps-matter/3432)
- Assetto Corsa: AO makes car surfaces "more defined in each lighting condition"; cars without it "tend to look dated"; baked AO maps are usual on cars, with vertex AO from standalone bakers as an alternative. — [GTPlanet AC mods discussion, search excerpt](https://www.gtplanet.net/forum/threads/assetto-corsa-pc-mods-general-discussion.307899/post-13302790)

### Inferences
- **For the Nova (AC, high detail):** the ragged gap edges are best fixed by making each gap lip a clean, sharp-marked boundary: (a) mark the lip edges sharp so normals split there, (b) relax or straighten the lip vertices (Relax Face Sets or a short quad strip, Q5/Q3), (c) give each lip a small turned-in return face (1-3 mm) so the gap reads dark from any angle, and (d) back it with a dark shut face or jamb. A 1989 Nova's real gaps are probably in the 4-6 mm range (older cars per the Capital One figure); keep the existing gap width.
- **Transfer exclusion:** in the normal-transfer pass (Q1), weight the gap lip bands to 0 so the smoothed proxy does not round the lips.
- **Darkening:** an AO bake (or AC's own AO texture slot on the body material) darkens the gap interior cheaply. Combine geometry gaps with AO rather than relying on normals alone.
- If panels are later separated for opening doors or bonnet, Gabester's approach (detach, offset a few mm, simple underside on the same grid, jamb as the inverse of the door) is the established pattern.

### Gaps
- I found no Assetto Corsa / Kunos-specific guidance on how official AC cars model or shade panel gaps, and nothing on whether AC's car paint shader uses a normal map for gaps.
- The 80.lv vehicle article does not cover panel gaps; the full Polycount panel-gap threads could not be read.

## 5. Smoothing tools that preserve volume/features: which are safe on car panels

### Takeaway
Use smoothers that can be masked and pinned. In order of control: Smooth Laplacian modifier (curvature-flow, built for noisy real-world meshes, Preserve Volume, vertex group), Corrective Smooth in "Only Smooth" mode (Length Weight, Pin Boundaries, vertex group), sculpt Mesh Filter "Surface Smooth" (Shape Preservation) and "Relax" (redistributes vertices without changing volume) with masks, and edit-mode Smooth Vertices on a selection. Avoid plain Smooth or high-iteration smoothing on the whole body: it shrinks curvature and rounds creases. Always measure displacement against an untouched copy.

### Cited Findings
- **Smooth Laplacian modifier**: "reduce noise on a mesh's surface with minimal changes to its shape"; "useful for objects that have been reconstructed from the real world and contain undesirable noise"; curvature-flow Laplace-Beltrami operator. Options: Repeat, **Lambda Factor** ("Using a small Factor, you can remove noise from the shape without affecting desirable geometry"), **Lambda Border** (separate control for border edges), **Preserve Volume** (reduces shrinkage), **Normalized** (when disabled "geometry spikes may occur"), Vertex Group (+ Invert), per-axis toggles. Warning: "Meshes with ... more than ten thousand (10,000) [vertices] may take several minutes for processing. You can use small portions of the mesh for testing." — [Blender Manual: Smooth Laplacian Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/deform/laplacian_smooth.html)
- **Corrective Smooth modifier**: designed to "reduce highly distorted areas of a mesh by smoothing the deformations", typically after an Armature. Options: Factor, Repeat, Scale, **Smooth Type** (Simple; **Length Weight** "can give higher quality smoothing in some cases, by better preserving the shape"), Vertex Group, **Only Smooth** ("to preview the smoothing used, before correction is applied"), **Pin Boundaries** ("Prevent boundary vertices from smoothing"), Rest Source (Original Coordinates needs the same vertex count; Bind Coordinates). — [Blender Manual: Smooth Corrective Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/deform/corrective_smooth.html)
- **Smooth Vertices** (edit mode, Vertex menu): moves selected vertices so the surface "becomes more smooth and rounded"; Smoothing factor, Repeat, Axes. Not to be confused with Shade Smooth, which "merely changes the vertex normals". **Smooth Vertices (Laplacian)** is the edit-mode version of the Laplacian modifier. — [Blender Manual: Smooth Vertices](https://docs.blender.org/manual/en/latest/modeling/meshes/editing/vertex/smooth_vertices.html); [Blender Manual: Smooth Vertices (Laplacian)](https://docs.blender.org/manual/en/latest/modeling/meshes/editing/vertex/laplacian_smooth.html)
- **Sculpt Mesh Filter** (respects masking, auto-masking and visibility): **Surface Smooth** "Eliminates irregularities ... while preserving the volume", with **Shape Preservation** and **Per-Vertex Displacement**; **Relax** "Tries to create an even distribution of quads without deforming the volume of the mesh"; **Relax Face Sets** "will remove the jagged lines visible after drawing or creating a face set"; **Sharpen** "Sharpens and smooths the mesh based on its curvature, resulting in pinching hard edges and polishing flat surfaces" (useful for hard surfaces), with Smooth Ratio, Intensify Details, Curvature Smooth Iterations; Deformation Axis can lock movement to an axis. — [Blender Manual: Mesh Filter](https://docs.blender.org/manual/en/latest/sculpt_paint/sculpting/tools/mesh_filter.html)
- **Smooth by Angle** modifier: a Geometry Nodes asset in the Essentials library that "Sets the sharpness of mesh edges based on the angle between the neighboring faces"; options Angle and Ignore Sharpness; added with Shade Auto Smooth. It changes edge sharpness only, not positions. — [Blender Manual: Smooth By Angle Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/normals/smooth_by_angle.html)
- Strip micro-noise before retopology so the cage follows the main forms. — [Sloyd: manual retopology guide](https://www.sloyd.ai/blog/manual-retopology-for-sculpted-models-step-by-step-guide)

### Inferences
- **Safe-on-car-panels ranking (inferred from the manual's own descriptions):**
  - *Smooth Laplacian*, low Lambda Factor, several Repeats, Preserve Volume + Normalized on, Lambda Border 0 (keeps open edges such as panel-gap lips still), with a vertex group painted on the rippled bumper and sill bands. Closest Blender match to a Taubin-style volume-preserving denoiser. Run it on separated panels or a vertex group because of the 1.2M-vertex cost.
  - *Corrective Smooth*, **Only Smooth** on (inferred: on an undeformed static mesh, the normal corrective mode has no deformation to correct, so Only Smooth is the mode that actually smooths), Length Weight, Pin Boundaries, vertex group. Ideal for making the smoothed twin in Q1, where displacement does not matter.
  - *Sculpt Surface Smooth / Relax* with masks on creases and gaps: good for interactive local fixes on crumpled spots. Relax evens out the triangle distribution, which helps the zig-zag look without moving the surface much.
  - *Relax Face Sets* (to test): give each panel or each side of a crease its own face set (e.g. Face Sets from edit-mode selection or by normals), then run Relax Face Sets to smooth the boundary line. This is the most direct built-in tool for jagged crease lines and ragged panel-gap edges.
  - *Sharpen* filter with crease bands masked in: tightens crease lines while polishing flats; risky on a gently curved body, use at low strength.
  - *Edit-mode Smooth Vertices* on a selection: unselected vertices do not move, so selection edges act as pins. Fine for small patches, crude for large areas.
  - Avoid: plain Smooth modifier on the whole body, Laplacian with high factor, Sharpen without masks.
- **Displacement check:** keep an untouched copy and measure (e.g. a Geometry Nodes Sample Nearest Surface distance to a colour attribute, or a quick Python script) so that smoothing stays within the 1-2 mm budget except on crumpled panels.

### Gaps
- No source reports numeric settings (Factor/Repeat) tested on car bodies; values must be tuned on a panel copy.
- Blender has no named Taubin smoother; the Laplacian "Preserve Volume" option is the nearest equivalent, but I found no source comparing them.
- LoopTools (Space/Curve for straightening edge loops) was not researched; whether it is still bundled or an extension in 5.x is unverified.

## 6. Baking a normal map from the high-poly to a cleaner low-poly as an alternative

### Takeaway
Baking is the standard high-to-low route for detail, but car-game practitioners rarely bake whole bodies. Body shading comes from clean mid-poly geometry and vertex normals; normal maps are kept for wheels, tyres, interiors and small detail. Baking the current noisy mesh would also bake its noise. For the Nova it only makes sense after a clean retopo (Q3), and then mainly for small detail and gaps.

### Cited Findings
- Blender **Selected to Active** bake: "The rays are cast from the low-poly object inwards towards the high-poly object"; adjust with Max Ray Distance or Extrusion, or use a **Cage** ("a ballooned-out version of the low-poly mesh"); without a cage "the rays will conform to the mesh normals. This produces glitches on the edges". High-poly objects can be joined first to save memory. — [Blender Manual: Cycles Baking](https://docs.blender.org/manual/en/latest/render/cycles/baking.html)
- Gabester (BeamNG): "almost never" bakes normal maps for whole cars (interiors excepted); gaps done with mask-derived normal maps instead. — [BeamNG: Gabester's vehicle workflow](https://beamng.com/posts/37582/)
- Rookies Ford GT for games: only the alloy wheels were modelled high-poly and baked to a low-poly normal map. — [The Rookies (Rinalds Bitte, 2024)](https://www.therookies.co/blog/breakdowns/production-process-vehicle-assets-games)
- 80.lv: car detail is "either baked or modeled using smoothed normals" (mid poly); tyre sidewall pattern drawn as vectors and used "as a height/bump map". — [80.lv: Vehicle Production for Games](https://80.lv/articles/vehicle-production-for-games/)
- Polycount: vertex-normal transfer avoids "texture compression or interpolation artifacts"; baking a smooth high-poly onto a smooth low-poly mostly gives a flat normal map, and baking hard edges onto a fully smooth low forces "an extremely sharp border between radically different colors on every hard edge". — [Polycount 2426371, search excerpt only](https://polycount.com/discussion/comment/2426371); [Polycount 2256387, search excerpt only](https://polycount.com/discussion/comment/2256387)

### Inferences
- **Why it is a poor fit now:** (a) it needs a clean low-poly first, which is the expensive retopo of Q3; (b) baking from the current mesh reproduces its ripples in the map; (c) texture resolution limits apply. A 4096 px map spread over an unwrapped ~3.6 m Nova body gives roughly 1-2 mm per texel before padding, too coarse for crisp gap lips; (d) map compression and mip-mapping add the artifacts Polycount warns about.
- **Where it does fit:** wheels, badges, grilles, vents, small trim and gap-edge bevels (Gabester's mask-to-normal trick), on top of a clean geometry body.
- **Hybrid that fits AC:** keep the dense geometry, fix shading with normal transfer (Q1), and bake only AO (and optionally a gap mask) for the body.

### Gaps
- I did not find authoritative information on whether AC's car paint shaders (ksPerPixelMultiMap and CSP variants) use a normal map on the body, or on Kunos's body poly budgets for LOD A.

## 7. Overall: what to do on the Nova body, in order (objective summary)

### Takeaway
Fix shading first with normals (no shape change), then make small masked geometry fixes, then rebuild only what is genuinely broken. That matches how game car artists keep surfaces continuous (one smoothing group per panel, sharp only at cut lines, a reflective matcap as the check), using only built-in Blender 5.x tools.

### Cited Findings
- Normal transfer is the recommended fix for racing-game car meshes where hand-averaging fails. — [Polycount 2426371, search excerpt only](https://polycount.com/discussion/comment/2426371)
- Topology mapping suits "a destination mesh that's a deformed copy of the source"; vertex-group mixing and Max Distance are available. — [Blender Manual: Data Transfer](https://docs.blender.org/manual/en/latest/modeling/modifiers/modify/data_transfer.html)
- In 4.1+, custom normals are used automatically and sharpness lives in the `sharp_edge` attribute. — [Blender 4.1 Release Notes](https://developer.blender.org/docs/release_notes/4.1/modeling/)
- Smooth Laplacian is designed for noisy real-world meshes with minimal shape change; Mesh Filter Surface Smooth / Relax / Relax Face Sets respect masks. — [Blender Manual: Smooth Laplacian](https://docs.blender.org/manual/en/latest/modeling/modifiers/deform/laplacian_smooth.html); [Blender Manual: Mesh Filter](https://docs.blender.org/manual/en/latest/sculpt_paint/sculpting/tools/mesh_filter.html)
- One smoothing group per shell, split only at panel cutlines; gaps a few mm with simple undersides and jambs. — [BeamNG: Gabester's workflow](https://beamng.com/posts/37582/)
- Reflective matcap as the shading check. — [The Rookies (Rinalds Bitte, 2024)](https://www.therookies.co/blog/breakdowns/production-process-vehicle-assets-games)

### Inferences
- **Suggested order (each step on a BACKUP-named copy, deploy only after a CM showroom check):**
  1. Mark sharp edges on the true creases and all panel-gap lips; make vertex groups `crease_band`, `gap_lips`, `ripple_bands` (bumpers, sills), `crumpled`.
  2. Make the smoothed twin (Corrective Smooth Only Smooth / Laplacian, with `crease_band` + `gap_lips` excluded) and transfer Custom Normals with Topology mapping, mix limited by an inverted `crease_band + gap_lips` group. Check with a reflective matcap. Expect most streaks and ripples to disappear from shading at zero displacement.
  3. Where ripples still show on the silhouette or in grazing reflections, apply a Smooth Laplacian (low factor, Preserve Volume) on `ripple_bands` only, measuring displacement (≤1-2 mm). Then re-run step 2 because the geometry changed.
  4. Jagged crease and gap lines: try sculpt Relax Face Sets with face sets per panel; if not enough, rebuild a quad strip along the worst creases (shrinkwrapped, subdivided) and stitch it in.
  5. Crumpled panels: local quad patch, Subdivision 1-2, Shrinkwrap (Target Normal Project) to a smoothed reference, replace the triangles.
  6. Apply all modifiers, export FBX, confirm in ksEditor and the CM showroom that custom normals survived. Bake AO for gap darkening.
- Optional: a Weighted Normal pass (Face Area, Keep Sharp) on `crease_band` only, if sliver triangles still cause sawtooth shading beside creases.

### Gaps
- None of these steps has a published before/after on a comparable bought car mesh; each should be tested on one panel (e.g. the front bumper) before the whole body.
- No AC-community source confirms custom split normals survive the FBX → ksEditor → KN5 path; this needs a direct test.
